# `summarize`: three outputs per run — long record (Qwen) + summaries from Qwen and Gemma

## Context

`~/bin/summarize` currently produces one output: an exhaustive meeting record from a transcript via a local llama.cpp server running Qwen3-27B. The user wants each run to produce:

1. **Long record** (existing prompts, unchanged) — generated by **Qwen** only. Filename must contain "long".
2. **Summary notes** — normal meeting notes, no length target given to the model, with an explicit instruction to capture people's self-introductions in detail. Generated **twice: once by Qwen, once by Gemma** (Gemma naturally summarizes more; user wants to compare).

Decisions from the user:
- All three by default in one invocation; flags to select subsets.
- No prescribed summary length — just instruct and see what the model produces.
- Gemma model: `~/llms/gemma/4/bartowski-31B-it-Q8_0.gguf` (the one in shell history).
- Long record from Qwen only.

Constraint discovered: this llama.cpp build loads **one model per llama-server process** (no router/multi-model support). Approach chosen: **swap models within the script** — detect the loaded model via `/v1/models`, restart the server with the other model when needed. Run order groups by model so there's exactly one swap: Qwen long → Qwen summary → (swap) → Gemma summary.

## File to modify

`/home/dcar/bin/summarize` (only file touched)

## Changes

### 1. Model configs

Replace the single `MODEL_PATH`/`MODEL_ID` constants with a `MODELS` dict:

- `qwen`: path `~/llms/qwen3/6/mtp-27B-UD-Q8_K_XL.gguf`, server args as today (`--spec-type draft-mtp --spec-draft-n-max 3 -ngl 999 -c 128000 -fa off -ctk q8_0 -ctv q8_0 --temp 0`).
- `gemma`: path `~/llms/gemma/4/bartowski-31B-it-Q8_0.gguf`, server args from the user's known-working launch: `-ngl 999 -c 128000 --no-mmap --temp 0 --no-warmup` (use 128000 ctx to match qwen; history used 256000 but 128k is what the script standardizes on).

### 2. Prompt sets

Keep existing `SYSTEM_PROMPT`/`USER_PROMPT_PREFIX` text verbatim as the **long** mode. Add a **summary** mode:

- System: "You are an expert transcription analyst. Produce clear, well-organized meeting notes from the transcript. Use markdown formatting with clear headers, bullet points, and tables for structured data."
- User prefix: "Here is the full transcript of a meeting. Generate meeting notes covering the topics discussed, decisions made, and action items. When people introduce themselves, capture those introductions in detail — name, role, organization, background, and anything else they say about themselves. Include a list of attendees and a table of Action Items."

No length instruction in the summary prompts (per user: let the LLM decide).

Note: transcripts mix enrolled real names and raw `SPEAKER_NN` labels (`[HH:MM:SS --> HH:MM:SS] Name: text`); the introduction-capture instruction doubles as a way to tie `SPEAKER_NN` labels to spoken self-introductions.

### 3. Server management — model-aware ensure/swap

- `get_loaded_model(url)`: GET `/v1/models`, return the reported model id (contains the gguf basename); `None` if not responding.
- `ensure_server(model_cfg)`: if the running server already has the right gguf (match on basename), reuse it. If a llama-server is running with a *different* model, terminate it (psutil: find `llama-server` procs, `terminate()`, wait, `kill()` fallback), then start the requested model via the existing `start_server()` logic (parameterized with the model's args). Keep the existing 5-minute readiness poll.
- The last-used server is left running after the script exits (same behavior as today).

### 4. Jobs and output naming

Default run = three jobs in this order (one model swap total):

| Job | Model | Prompts | Output |
|---|---|---|---|
| long | qwen | existing detailed prompts | `<transcript>.long.md` |
| summary-qwen | qwen | summary prompts | `<transcript>.summary-qwen.md` |
| summary-gemma | gemma | summary prompts | `<transcript>.summary-gemma.md` |

- If the optional positional `output` is given, treat it as a base path: strip a trailing `.md` and derive `<base>.long.md`, `<base>.summary-qwen.md`, `<base>.summary-gemma.md`.
- Selection flags: `--long-only`, `--summary-only` (both summaries), `--qwen-only`, `--gemma-only` (summary-gemma only, since long is qwen). Combinable where sensible; keep implementation simple — filter the job list.
- `generate_summary()` gains `system_prompt` and `user_prefix` parameters (currently reads module globals at `summarize:120-121`); read the transcript once in `main()` and pass the text. Per-job print messages say which model/mode is generating.
